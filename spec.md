# Техническое задание: Galchanskiy Studio

## 1. Описание проекта

Разработать официальный сайт **Galchanskiy Studio** — небольшой технологической студии, занимающейся разработкой программного обеспечения с активным использованием искусственного интеллекта.

Сайт должен представлять студию и её программные продукты.

**Основная идея:** современный, минималистичный сайт с элементами эстетики программирования. Без корпоративного пафоса, громких заявлений и лишней информации.

В качестве основного визуального референса использовать предоставленный утверждённый макет.

## 2. Технологический стек

- Backend: Python 3.12+, Flask.
- Шаблонизатор: Jinja2.
- Frontend: HTML5, CSS3, Vanilla JavaScript.
- Иконки: Lucide или локальные SVG.
- Шрифты: Inter для основного текста, JetBrains Mono для технических элементов.
- WSGI: Gunicorn.
- Веб-сервер для production: Nginx.

Не использовать React, Vue, Tailwind, Bootstrap, Node.js, npm и другие инструменты, не требующиеся для такого сайта.

Не использовать базу данных. Для текущего функционала она не нужна.

Сохранить стиль утверждённого макета:

- Тёмный сине-графитовый фон.
- Зелёно-бирюзовые акценты.
- Ненавязчивая техническая сетка на фоне.

- Достаточное количество свободного пространства.

Сайт должен выглядеть технологично, но не превращаться в имитацию терминала.

**G/ | Galchanskiy Studio**

- Иконка GitHub, ведущая на профиль студии или разработчика.

## 6. Главный блок

### Заголовок

**Разработка полезного софта.**

Слово «софта» выделить зелёным цветом.

### Описание

«Веб-сервисы, приложения и инструменты. Используем ИИ на полную катушку.»

### Технологические метки

Три небольших элемента:

- Software
- AI-powered
- Engineering

Использовать аккуратные иконки и полупрозрачные поверхности.

Метки информационные, без функциональности.

### Декоративная графика

Справа от текста разместить стилизованное окно редактора кода.

Оно должно:
- Иметь небольшую перспективу или наклон.
- Содержать абстрактные строки кода.
- Использовать приглушённые зелёные, синие и фиолетовые оттенки.
- Не отвлекать внимание от заголовка.
- Корректно адаптироваться к мобильным экранам.

Реализовать средствами HTML/CSS/SVG.

Не использовать тяжёлые изображения, видео или WebGL.

### Фон

Создать многослойный фон:

1. Основной тёмный градиент.
2. Очень слабая сетка из тонких линий.
3. Небольшие декоративные точки в узлах сетки.
4. Одна или две полупрозрачные диагональные зелёные фигуры справа.
5. Локальное мягкое зелёное свечение.

Все элементы должны быть сдержанными.

Не добавлять яркие неоновые волны, крупные светящиеся сферы и чрезмерные анимации.

Каждая карточка содержит:
- Иконку проекта.
- Название.
- Краткое описание.

- Небольшой тематический декоративный рисунок на фоне.

Карточки должны быть одинаковой высоты на десктопе.

### Проект 1 — Library

Название: **Library**

Описание:

«Управление книгами и библиотечным каталогом.»

Иконка: открытая книга.

Фоновая графика: крупный полупрозрачный контур книги.

Акцент: зелёно-бирюзовый.

Кнопка: **Открыть сайт**

Действие: переход на существующий сайт Library.

### Проект 2 — Guitar Tuner

Название: **Guitar Tuner**

Описание:

«Точный офлайн-тюнер для гитары и баса.»

Иконка: гитарный гриф или головка грифа.

Фоновая графика: полупрозрачный силуэт гитары.

Акцент: тёплый золотистый, согласованный с общей зелёной палитрой.

Кнопка: **Подробнее**

Действие: переход на `/projects/guitar-tuner`.

### Интерактивность карточек

При наведении:
- Небольшое изменение цвета границы.
- Лёгкое поднятие карточки.
- Мягкое усиление фонового свечения.
- Плавная анимация кнопки.

Не использовать чрезмерные трансформации и вращения.

## 8. Страница Guitar Tuner

Оформить в едином стиле с главной страницей.

### Первый экран

- Название Guitar Tuner.
- Подзаголовок: «Простой и точный тюнер для Android».
- Краткое описание.
- Кнопка «Скачать APK».
- Крупный скриншот приложения в аккуратной рамке смартфона.

### Возможности

Показать компактный список:

- Поддержка шестиструнной гитары.
- Поддержка четырёхструнной бас-гитары.
- Автоматическое определение струны.
- Стрелочный индикатор отклонения.
- Работа без интернета.
- Отсутствие рекламы.

### Скриншоты

Предусмотреть возможность добавления нескольких реальных скриншотов.

Если скриншотов пока нет, не подменять их выдуманными изображениями приложения. Использовать аккуратное временное оформление.

### Информация о версии

Отображать:
- Версию приложения.
- Минимальную версию Android.
- Размер APK, если файл доступен.
- Дату выпуска, если она задана.

### Скачивание

Маршрут:

`/downloads/guitar-tuner.apk`

Файл хранится локально на сервере или в настроенном каталоге релизов.

Flask должен безопасно отдавать файл с корректными HTTP-заголовками.

Если APK отсутствует:
- Не показывать неработающую ссылку.
- Вместо кнопки выводить «Скоро будет доступно».

Никакой регистрации для скачивания не требуется.

## 10. Адаптивность

Поддерживать:
- Смартфоны от 320 px.
- Планшеты.
- Ноутбуки.
- Широкие мониторы.

Особенности мобильной версии:
- Заголовок переносится естественным образом.
- Декоративное окно кода уменьшается или скрывается.
- Карточки располагаются вертикально.
- Кнопки остаются удобными для нажатия.
- Нет горизонтального скролла.
- Текст остаётся читаемым.

## 11. Анимации

Использовать CSS transitions и, при необходимости, небольшое количество JavaScript.

Допустимые эффекты:
- Плавное появление контента.
- Подсветка карточек.
- Мягкие hover-эффекты.
- Плавная прокрутка к проектам.

Учитывать `prefers-reduced-motion`.

Не добавлять постоянно движущиеся частицы, сложные параллакс-эффекты и тяжёлые анимационные библиотеки.

## 12. Backend Flask

### Маршруты

- `GET /` — главная страница.
- `GET /projects/guitar-tuner` — страница тюнера.
- `GET /downloads/guitar-tuner.apk` — скачивание APK.
- `GET /health` — простой health-check для мониторинга.

### Конфигурация

Вынести в отдельный конфигурационный модуль:
- Название студии.
- URL Library.
- URL GitHub.
- Данные Guitar Tuner.
- Путь к APK.
- Версию приложения.
- Минимальную версию Android.

Данные проектов хранить в Python-структуре или JSON-файле.

Не использовать базу данных.

### Безопасность

- Не включать Flask debug в production.
- Не принимать произвольные пути файлов от пользователя.
- Не допускать path traversal при скачивании.
- Использовать безопасную обработку конфигурации.
- Не создавать административную панель.
- Не добавлять ненужные API.
- Не использовать пользовательские cookie для аналитики или отслеживания.

Не изменять существующие приложения и конфигурации сервера без явного разрешения.
